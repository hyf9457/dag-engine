## 1. 设计约束



| 约束        | 说明                                                                |
| --------- | ----------------------------------------------------------------- |
| MySQL 5.6 | 无 `FOR UPDATE SKIP LOCKED`、无 JSON 类型、无 CTE → 防重靠 CAS，图 / 结果存 TEXT |
| id 字段     | 全部为 VARCHAR (64)，引擎生成（UUID 或雪花字符串）                                |
| 状态流转      | 全部为单行 CAS 条件更新（`UPDATE ... WHERE ... AND state=?`），影响行数判定         |
| 图结构       | edges 不建表；graph\_json 存于 task\_instance，运行时解析为内存邻接表（任务级缓存）        |
| 无长事务      | 仅 "提交" 和 "终态 + 收敛" 两个短事务，其余全部单条 SQL                               |

## 2. 表结构 DDL

### 2.1 flow\_definition（流程定义・静态）



```
CREATE TABLE flow\_definition (

&#x20; id          VARCHAR(64)  NOT NULL COMMENT '定义id',

&#x20; biz\_type    VARCHAR(64)  NOT NULL COMMENT '业务类型',

&#x20; biz\_id      VARCHAR(64)  NOT NULL COMMENT '业务主键',

&#x20; graph\_json  TEXT         NOT NULL COMMENT 'DAG图（nodes+edges）',

&#x20; version     INT          NOT NULL DEFAULT 1 COMMENT '版本',

&#x20; status      VARCHAR(16)  NOT NULL DEFAULT 'ENABLE' COMMENT 'ENABLE/DISABLE',

&#x20; created\_at  DATETIME     NOT NULL COMMENT '创建时间',

&#x20; updated\_at  DATETIME     NOT NULL COMMENT '更新时间',

&#x20; PRIMARY KEY (id),

&#x20; UNIQUE KEY uk\_biz (biz\_type, biz\_id)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='流程定义';
```

### 2.2 task\_instance（任务表）



```
CREATE TABLE task\_instance (

&#x20; task\_id     VARCHAR(64) NOT NULL COMMENT '任务id（引擎生成）',

&#x20; biz\_type    VARCHAR(64) NOT NULL COMMENT '业务类型',

&#x20; biz\_id      VARCHAR(64) NOT NULL COMMENT '业务主键',

&#x20; graph\_json  TEXT        NOT NULL COMMENT '本次运行图快照（nodes+edges）',

&#x20; state       VARCHAR(16) NOT NULL DEFAULT 'RUNNING' COMMENT 'RUNNING/SUCCESS/FAILED/CANCELLED',

&#x20; biz\_args    TEXT        NULL COMMENT '全局业务参数JSON（submit 接口传入）',

&#x20; started\_at  DATETIME    NULL COMMENT '开始时间',

&#x20; finished\_at DATETIME    NULL COMMENT '结束时间',

&#x20; created\_at  DATETIME    NOT NULL COMMENT '创建时间',

&#x20; updated\_at  DATETIME    NOT NULL COMMENT '更新时间',

&#x20; PRIMARY KEY (task\_id),

&#x20; UNIQUE KEY uk\_biz (biz\_type, biz\_id),

&#x20; KEY idx\_state (state)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务表';
```



* `uk_biz`：幂等键，重复提交返回已有任务

* `idx_state`：活跃任务扫描（`state='RUNNING'`）

### 2.3 node\_instance（节点表，提交时由 graph\_json 解析生成）



```
CREATE TABLE node\_instance (

&#x20; id          VARCHAR(64)  NOT NULL COMMENT '节点实例id（引擎生成）',

&#x20; task\_id     VARCHAR(64)  NOT NULL COMMENT '所属任务',

&#x20; biz\_node\_id VARCHAR(64)  NOT NULL COMMENT '用户定义节点唯一id',

&#x20; handler     VARCHAR(128) NOT NULL COMMENT '执行器bean名（@Component名）',

&#x20; state       VARCHAR(16)  NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/RUNNING/WAIT\_CONFIRM/SUCCESS/FAILED/CANCELLED',

&#x20; result      TEXT         NULL COMMENT '执行结果（handler回写；超时/异常由引擎填）',

&#x20; biz\_args    TEXT         NULL COMMENT '节点业务参数（来自 graph\_json nodes[].biz\_args）',

&#x20; time\_out    TINYINT      NOT NULL DEFAULT 0 COMMENT '是否超时（引擎填写）',

&#x20; async\_type  TINYINT      NOT NULL DEFAULT 0 COMMENT '0同步/1异步（来自graph\_json节点定义）',

&#x20; started\_at  DATETIME     NULL COMMENT '开始时间',

&#x20; finished\_at DATETIME     NULL COMMENT '结束时间',

&#x20; created\_at  DATETIME     NOT NULL COMMENT '创建时间',

&#x20; updated\_at  DATETIME     NOT NULL COMMENT '更新时间',

&#x20; PRIMARY KEY (id),

&#x20; UNIQUE KEY uk\_task\_node (task\_id, biz\_node\_id),

&#x20; KEY idx\_task\_state (task\_id, state),

&#x20; KEY idx\_state\_started (state, started\_at)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='节点表';
```



* `uk_task_node`：任务内节点唯一（解析 graph\_json 生成时即保证）

* `idx_task_state`：任务节点查询 / 收敛检查（`COUNT(state<>'SUCCESS')`）

* `idx_state_started`：巡检器扫描 RUNNING 节点（`state='RUNNING' AND started_at < ...`）

### 2.4 task\_trace（任务流水表 · 单表双状态）

> 一张表同时呈现**任务整体状态（task\_state）与节点局部状态（node\_state）**，按 taskId + 时间排序即可还原完整运行轨迹。任务级事件只填 task\_state；节点级事件同时填两者（task\_state 为冗余快照，便于整体观察）。

```
CREATE TABLE task\_trace (

&#x20; id           VARCHAR(64) NOT NULL COMMENT '流水id',

&#x20; task\_id      VARCHAR(64) NOT NULL COMMENT '所属任务',

&#x20; node\_id      VARCHAR(64) NULL COMMENT '节点实例id（节点级事件；任务级为空）',

&#x20; biz\_node\_id  VARCHAR(64) NULL COMMENT '节点业务id（可读性）',

&#x20; event\_type   VARCHAR(32) NOT NULL COMMENT '事件类型',

&#x20; task\_state   VARCHAR(16) NOT NULL COMMENT '事件后任务状态（快照）',

&#x20; node\_state   VARCHAR(16) NULL COMMENT '事件后节点状态（节点级事件）',

&#x20; detail       TEXT        NULL COMMENT '附加信息（来源/模式/结果/操作）',

&#x20; created\_at   DATETIME    NOT NULL COMMENT '事件时间',

&#x20; PRIMARY KEY (id),

&#x20; KEY idx\_task\_time (task\_id, created\_at),

&#x20; KEY idx\_node\_time (node\_id, created\_at)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务流水';
```

**事件清单与记录规则（怎么记）**：

| 事件 | 层级 | node_id | task_state 记 | node_state 记 | detail 记 |
|---|---|---|---|---|---|
| TASK_SUBMIT | 任务 | 空 | RUNNING | 空 | 来源：固定/自定义 |
| NODE_CLAIM | 节点 | 填 | RUNNING | RUNNING | 执行器名 |
| NODE_SUCCESS | 节点 | 填 | 收敛后（RUNNING / SUCCESS） | SUCCESS | result |
| NODE_FAILED | 节点 | 填 | 收敛后（FAILED） | FAILED | error |
| NODE_WAIT_CONFIRM | 节点 | 填 | RUNNING | WAIT_CONFIRM | — |
| NODE_CONFIRM | 节点 | 填 | 收敛后 | SUCCESS / FAILED | result / error |
| NODE_TIMEOUT | 节点 | 填 | 收敛后（FAILED） | FAILED | 超时阈值 |
| NODE_RESET | 节点 | 填 | RUNNING | PENDING | source=inspect / retry |
| RESUME | 节点 | 填 | RUNNING | PENDING | source=user |
| NODE_CANCEL | 节点 | 填 | CANCELLED | CANCELLED | source=cancel / forceFinalize |
| TASK_CANCEL | 任务 | 空 | CANCELLED | 空 | source |
| RETRY | 任务 | 空 | RUNNING | 空 | mode=CONTINUE / RESTART |
| FORCE_FINALIZE | 任务 | 空 | 目标态 | 空 | 目标 + 原因 |

**收敛合并规则**：节点进入终态若触发任务收敛（最后一个节点成功 / 首个节点失败），同一条流水的 task\_state 直接记收敛终态；未触发则记 RUNNING。**最后一行流水 = 任务最终状态**。

**重试 / 重跑 / 续跑 / 巡检怎么记**：

- 重试 CONTINUE：1 条 `RETRY`（task FAILED→RUNNING，detail: mode=CONTINUE）＋ 每个 FAILED/WAIT_CONFIRM 节点 1 条 `NODE_RESET`（detail: source=retry）→ 之后正常 CLAIM → 终态
- 重跑 RESTART：1 条 `RETRY`（detail: mode=RESTART）＋ 全部节点 `NODE_RESET`（含原 SUCCESS 节点，detail: source=retry-restart）→ 根节点起全量重跑
- 断点续跑 resume：1 条 `RESUME`（node WAIT_CONFIRM→PENDING，detail: source=user）→ 重新 CLAIM
- 巡检异常重置：1 条 `NODE_RESET`（node RUNNING→PENDING，detail: source=inspect）→ 重新 CLAIM

**示例（A→B→C 串行，B 失败后 retry CONTINUE 重试）**：

| # | event | task_state | node_state | detail |
|---|---|---|---|---|
| 1 | TASK_SUBMIT | RUNNING | — | 固定流程 |
| 2 | NODE_CLAIM | RUNNING | A RUNNING | handlerA |
| 3 | NODE_SUCCESS | RUNNING | A SUCCESS | result |
| 4 | NODE_CLAIM | RUNNING | B RUNNING | handlerB |
| 5 | NODE_FAILED | FAILED | B FAILED | error |
| 6 | RETRY | RUNNING | — | mode=CONTINUE |
| 7 | NODE_RESET | RUNNING | B PENDING | source=retry |
| 8 | NODE_CLAIM | RUNNING | B RUNNING | handlerB |
| 9 | NODE_SUCCESS | RUNNING | B SUCCESS | result |
| 10 | NODE_CLAIM | RUNNING | C RUNNING | handlerC |
| 11 | NODE_SUCCESS | SUCCESS | C SUCCESS | 末节点收敛 |

**写入约定**：与状态变更同短事务（§3.1-§3.8 各 CAS 成功后追加）；流水不参与状态判定，仅审计轨迹；写入失败可重试，不影响主流程。

**查询**：

```
-- 全轨迹：按 taskId 时间升序
SELECT id, node\_id, biz\_node\_id, event\_type, task\_state, node\_state, detail, created\_at
FROM task\_trace WHERE task\_id=? ORDER BY created\_at ASC;

-- 单节点轨迹（走 idx\_node\_time）
SELECT id, task\_id, event\_type, task\_state, node\_state, detail, created\_at
FROM task\_trace WHERE node\_id=? ORDER BY created\_at ASC;
```

## 3. 关键 SQL 草案（全部 CAS）

> 约定：影响行数 = 1 表示状态转换成功；= 0 表示前置状态不匹配（已被其他路径处理 / 抢占），调用方按幂等忽略。

### 3.1 提交（幂等 + 短事务）



```
\-- ① 幂等检查

SELECT task\_id, state FROM task\_instance WHERE biz\_type=? AND biz\_id=?;

\-- 存在 → 返回已有任务，不重复执行

\-- ② 短事务：task + 全部 node 原子落库

BEGIN;

INSERT INTO task\_instance(task\_id, biz\_type, biz\_id, graph\_json, state, biz\_args, started\_at, created\_at, updated\_at)

VALUES (?, ?, ?, ?, 'RUNNING', ?, NOW(), NOW(), NOW());

INSERT INTO node\_instance(id, task\_id, biz\_node\_id, handler, state, async\_type, biz\_args, created\_at, updated\_at)

VALUES (?, ?, ?, ?, 'PENDING', ?, ?, NOW(), NOW()), ...;   -- 批量；biz\_args 来自 graph\_json nodes[].biz\_args

COMMIT;

\-- ③ 事务提交后，同一线程对根节点（无前驱）触发统一领取（push 入口）
```

### 3.2 统一领取（两段式：先 tryLock，再 CAS）



```
\-- tryLock("dag:node:{nodeId}") 成功后才执行：

UPDATE node\_instance SET state='RUNNING', started\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state='PENDING';

\-- 行数=1 → 领取成功，锁内执行 handler；行数=0 → 已被领取/取消，释放锁跳过
```

### 3.3 同步终态 / 异步挂起（handler 返回）



```
\-- 同步 SUCCESS

UPDATE node\_instance SET state='SUCCESS', result=?, finished\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state='RUNNING';

\-- 同步 FAILED（handler 抛异常）

UPDATE node\_instance SET state='FAILED', result=?, finished\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state='RUNNING';

\-- 异步挂起（返回 pending）

UPDATE node\_instance SET state='WAIT\_CONFIRM', updated\_at=NOW()

WHERE id=? AND state='RUNNING';

\-- 挂起成功后释放锁（等待确认期间无锁）
```

### 3.4 回调确认（进程内 API，幂等）



```
\-- confirm

UPDATE node\_instance SET state='SUCCESS', result=?, finished\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state='WAIT\_CONFIRM';

\-- fail

UPDATE node\_instance SET state='FAILED', result=?, finished\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state='WAIT\_CONFIRM';

\-- 行数=0 → 重复/晚到回调，幂等忽略
```

### 3.5 统一巡检器（合并 02 §4.4 超时扫描 + §4.5 异常扫描）

> 一次巡检、一个 tryLock 判定，语义清晰：锁在 = 执行器活着（走超时判定）；锁不在 = 执行中断（重置重执行）。



```
\-- 每周期（默认 1s）取 RUNNING 候选

SELECT id, task\_id, started\_at FROM node\_instance

WHERE state='RUNNING' AND started\_at < NOW() - INTERVAL 0 SECOND

LIMIT ?;

\-- 对每个候选：

\-- ① tryLock("dag:node:{nodeId}", 0)：

\--    抢到 → 原执行已中断（锁过期释放），持锁执行重置：

UPDATE node\_instance SET state='PENDING', started\_at=NULL, finished\_at=NULL,

&#x20;      result=NULL, time\_out=0, updated\_at=NOW()

WHERE id=? AND state='RUNNING';

\--    重置后释放锁，重新入调度（push 重新触发）

\-- ② 抢不到 → 执行器活着，做超时判定：

UPDATE node\_instance SET state='FAILED', time\_out=1, result='timeout',

&#x20;      finished\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state='RUNNING' AND started\_at < NOW() - INTERVAL ? SECOND;

\-- 未超时 → 跳过
```

### 3.6 任务收敛（终态 + 收敛 = 短事务）



```
\-- 节点进入终态（SUCCESS/FAILED）时，在同一事务内：

BEGIN;

\-- ① 节点 CAS（见 3.3）

UPDATE node\_instance SET state='SUCCESS', ... WHERE id=? AND state='RUNNING';

\-- ② 若影响行数=1 且新状态=SUCCESS → 收敛检查：

\--    (a) 全部节点 SUCCESS → 任务收敛 SUCCESS

UPDATE task\_instance SET state='SUCCESS', finished\_at=NOW(), updated\_at=NOW()

WHERE task\_id=? AND state='RUNNING';

\--    前置条件：SELECT COUNT(\*) FROM node\_instance WHERE task\_id=? AND state<>'SUCCESS' → =0

\--    (b) 新状态=FAILED → 任务收敛 FAILED（CAS 一次，不覆盖 SUCCESS/CANCELLED）

UPDATE task\_instance SET state='FAILED', finished\_at=NOW(), updated\_at=NOW()

WHERE task\_id=? AND state='RUNNING';

COMMIT;
```



* 多副本并发终态：各自 CAS 自己的 node 行，task 行锁串行化，后到者 UPDATE 影响 0 行 → 无操作

* 收敛兜底：提交前崩溃则节点终态未生效，巡检重新处理；提交后崩溃则收敛已随事务提交，一致

### 3.7 人工控制操作



```
\-- retry CONTINUE：仅 FAILED 任务

UPDATE task\_instance SET state='RUNNING', finished\_at=NULL, updated\_at=NOW()

WHERE task\_id=? AND state='FAILED';

UPDATE node\_instance SET state='PENDING', started\_at=NULL, finished\_at=NULL,

&#x20;      result=NULL, time\_out=0, updated\_at=NOW()

WHERE task\_id=? AND state IN ('FAILED','WAIT\_CONFIRM');

\-- 重置后 push 重新触发（前驱已 SUCCESS 的节点立即进入调度）

\-- retry RESTART：全部节点重置

UPDATE node\_instance SET state='PENDING', started\_at=NULL, finished\_at=NULL,

&#x20;      result=NULL, time\_out=0, updated\_at=NOW()

WHERE task\_id=?;

\-- cancel：仅 RUNNING 任务

UPDATE task\_instance SET state='CANCELLED', finished\_at=NOW(), updated\_at=NOW()

WHERE task\_id=? AND state='RUNNING';

\-- 未开始节点

UPDATE node\_instance SET state='CANCELLED', finished\_at=NOW(), updated\_at=NOW()

WHERE task\_id=? AND state IN ('PENDING','WAIT\_CONFIRM');

\-- 同步 RUNNING 终止（执行结果晚到 CAS 失败自动忽略）

UPDATE node\_instance SET state='CANCELLED', finished\_at=NOW(), updated\_at=NOW()

WHERE task\_id=? AND state='RUNNING';

\-- resume：仅 WAIT\_CONFIRM 节点

UPDATE node\_instance SET state='PENDING', updated\_at=NOW()

WHERE id=? AND state='WAIT\_CONFIRM';

\-- 强制终态（运维兜底）

UPDATE node\_instance SET state=?, finished\_at=NOW(), updated\_at=NOW()

WHERE id=? AND state IN ('PENDING','RUNNING','WAIT\_CONFIRM');

UPDATE task\_instance SET state=?, finished\_at=NOW(), updated\_at=NOW()

WHERE task\_id=? AND state='RUNNING';
```

### 3.8 兜底扫描（保险路径）



```
\-- 周期扫描：活跃任务 + 节点状态（内存判前驱，见 02 §4.2 兜底路径）

SELECT task\_id FROM task\_instance WHERE state='RUNNING';

SELECT id, biz\_node\_id, state FROM node\_instance WHERE task\_id=?;

\-- 内存判定 PENDING 且前驱全 SUCCESS → 逐个走 3.2 统一领取

\-- 正常时 push 已即时触发，本扫描几乎无事；崩溃重启后捡回丢失的推进
```

## 4. 事务边界汇总



| 操作          | 事务 / 原子性   | 说明                |
| ----------- | ---------- | ----------------- |
| 提交任务        | 短事务        | task + nodes + 流水原子落库 |
| 统一领取        | 短事务（锁外 CAS） | CAS + 流水；行数 = 1 才算成功 |
| 节点终态 + 任务收敛 | 短事务        | CAS + 收敛 + 流水，原子提交 |
| 回调确认        | 短事务        | CAS + 流水，幂等         |
| 巡检（超时 / 异常） | 短事务        | CAS × 2 + 流水，持锁重置 / 超时 FAILED |
| 人工控制        | 短事务        | CAS + 流水，均有前置状态校验   |
