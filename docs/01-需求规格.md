# 01 · 需求规格说明书（设计稿 v0.1）

> 状态：需求已与业务方逐条确认，本文为设计基线，后续文档（架构/数据库/接口/时序/异常）均以此为准。

---

## 1. 项目概述

构建一个**开箱即用的 DAG 流程引擎 Spring Boot Starter**（`dag-core`），供业务方引入依赖、少量配置即可编排任务流程。

- 技术栈：**JDK 8 + Spring Boot 2.5.x + Maven 多模块**（公司技术栈基线）
- 交付形态：`dag-core`（引擎 starter）+ `dag-demo`（接入示例与开发测试）
- 运行模式：单机内嵌调度；同一服务多实例部署时防重复执行
- 持久化：**MySQL 5.6.x**（必选）+ **Redis Cluster**（Redisson 锁，多实例建议开启，缺失时降级）
- 技术栈影响：MySQL 5.6 **无 `FOR UPDATE SKIP LOCKED`、无 JSON 类型** → 多实例防重以 CAS 条件更新为权威，graph_json/result/biz_args 以 TEXT 存储；Redisson 支持 Cluster 模式

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 流程定义 FlowDefinition | 流程的静态结构（节点 + 依赖边 + 超时等），存 `flow_definition` 表 |
| 任务 Task | 一次具体的流程运行（即流程实例），存 `task_instance` 表 |
| 节点实例 NodeInstance | 任务中某个节点的运行记录，存 `node_instance` 表 |
| handler / 执行器 | 业务方实现的节点执行 Bean，**以 Spring Bean 名称注册（与 @Component 注解名称一致）**，graph_json 中通过 handler 字段引用 |
| 同步节点 | handler 由引擎推动调用，执行完直接返回结果，无回调概念 |
| 异步节点 | handler 返回 pending，节点进入 WAIT_CONFIRM，由用户通过确认 API 主动回写结果 |
| biz_type / biz_id | 业务类型 + 业务主键，调用方自定义；`task_instance` 以 `UNIQUE(biz_type, biz_id)` 幂等 |
| 调度器 | 每实例内置的定时扫描任务，领取可执行节点 |
| 超时扫描 | 巡检 RUNNING 节点是否超过执行超时时间 |
| 异常扫描 | 巡检 RUNNING 节点是否执行中断（Redis 锁已过期） |

## 3. 范围

### 3.1 v1 包含

| 能力 | 说明 |
|---|---|
| DAG 编排 | 串行 / 并行 / 汇聚（join） |
| 流程定义双通道 | ① 固定流程：注册到 `flow_definition` 静态存储；② 自定义流程：运行时提交 JSON，校验可执行性后执行 |
| 自定义流程校验 | JSON Schema 结构校验 + DAG 环检测 + 节点 id 唯一 + 边引用存在 + 节点 handler 已注册 + 参数合法性；**校验失败拒绝落库** |
| 异步回调确认 | 仅**进程内 API**（`confirm` / `fail`）；不提供 HTTP 回调端点 |
| 超时 | 仅同步执行段（RUNNING）有超时；**超时时间由引擎统一配置（平台统一，节点不自定义）**；超时 → 节点 FAILED + `time_out=true`；异步等待段（WAIT_CONFIRM）无超时 |
| 取消 | 仅 RUNNING 实例可取消；终态拒绝 |
| 重试 | 流程级 retry，两种模式：CONTINUE（仅失败节点重置）/ RESTART（全量重置） |
| 断点续跑 | 节点级 resume，仅 WAIT_CONFIRM 节点可触发 |
| 崩溃恢复 | 提交后/执行中服务挂掉，重启后从 DB 恢复；异常扫描以 Redis 锁判定执行中断并重新调度 |
| 多实例防重 | CAS 条件更新（权威）+ Redisson 锁（临界区互斥 / 执行中断判定）；MySQL 5.6 无 SKIP LOCKED，候选领取用普通查询 + CAS |
| 接入方式 | 执行器以 Spring Bean 注册（handler = @Component 名称）；流程结构以 JSON 定义（固定 / 自定义双通道）；**注解驱动流程定义（@DagFlow）不做，v2 再说** |
| 运行轨迹 | 流水表（task_trace）记录全部状态变更，按 taskId + 时间排序可查完整运行轨迹 |

### 3.2 v1 明确不做（v2 候选）

条件分支、节点级自动重试、子流程嵌套、人工审批、可视化管理页、人工暂停/恢复（pause/resume）、HTTP 回调、补偿回滚、注解驱动流程定义（@DagFlow）。

## 5. 状态机

### 5.1 节点状态

```
PENDING ──调度领取(CAS)──▶ RUNNING
                              ├─ handler 同步返回 → SUCCESS
                              ├─ handler 抛异常  → FAILED (result=异常信息)
                              ├─ 超时扫描        → FAILED (time_out=true, result=超时信息)
                              └─ handler 返回 pending → WAIT_CONFIRM
WAIT_CONFIRM ──用户 confirm()──▶ SUCCESS
             ──用户 fail()──▶ FAILED
             ──用户 resume()──▶ PENDING（重新调度执行）
任意非终态 ──cancel──▶ CANCELLED（异步节点晚到回调自动忽略）
```

- 终态：SUCCESS / FAILED / CANCELLED
- **无 READY/TIMEOUT 独立状态**；超时以 `time_out` 字段标记
- 调度领取条件：节点 `PENDING` 且所有前驱节点均已 `SUCCESS`（join 语义天然包含在领取条件中）

### 5.2 任务状态（收敛规则）

| 条件 | 任务状态 |
|---|---|
| 全部节点 SUCCESS | SUCCESS |
| 任一节点 FAILED（CAS 收敛一次，仅一次） | FAILED |
| 用户主动 cancel | CANCELLED |
| 其他（含 WAIT_CONFIRM 未确认） | RUNNING |

- 任务收敛 FAILED 后不再调度新节点；已 RUNNING 节点自然结束，结果不影响已收敛终态
- 任务终态不可再流转（retry 是唯一例外路径：FAILED → RUNNING）

### 5.3 操作 × 状态流转（v4）

| 操作 | 触发者 | 节点状态变化 | 校验 / 约束 |
|---|---|---|---|
| submit | 调用方 | 创建任务：任务 RUNNING，全部节点 PENDING | biz_type+biz_id 幂等；可执行性校验 |
| 调度领取 | 调度器 | PENDING 且前驱全 SUCCESS → RUNNING | 先加 Redis 锁，再 CAS |
| 同步成功 | 引擎 | RUNNING → SUCCESS，后继满足前驱全 SUCCESS 即可领取 | 仅 RUNNING 可进入 |
| 同步失败 | 引擎 | RUNNING → FAILED（result 记录异常） | 仅 RUNNING |
| 同步超时 | 超时扫描 | RUNNING → FAILED（time_out=true） | 超时时间平台统一配置，仅同步节点生效 |
| 异步挂起 | 引擎 | RUNNING → WAIT_CONFIRM（释放锁） | — |
| 回调确认 | 用户进程内 API | WAIT_CONFIRM → SUCCESS / FAILED | 仅 WAIT_CONFIRM；重复回调 CAS 忽略 |
| 异常重执行 | 异常扫描 | 无锁的 RUNNING → PENDING（重新调度） | tryLock 成功即证明原执行已中断 |
| cancel | 用户 | PENDING → CANCELLED；同步 RUNNING 终止；WAIT_CONFIRM 标记取消 | 仅 RUNNING 实例 |
| retry CONTINUE | 用户 | FAILED 节点 → PENDING；实例 FAILED → RUNNING | 仅 FAILED 实例 |
| retry RESTART | 用户 | 全部节点 → PENDING；实例 FAILED → RUNNING | 仅 FAILED 实例 |
| resume | 用户 | WAIT_CONFIRM → PENDING | 仅 WAIT_CONFIRM 节点 |
| 强制终态（运维） | 运维 | 挂起节点/实例 → 指定终态 | 兜底出口，仅运维场景 |

## 6. 执行语义约束（硬约束）

1. **提交幂等**：`biz_type + biz_id` 唯一（task_instance 唯一约束）；重复提交返回已有任务，不重复执行
2. **无自动重试**：引擎不自动 retry；超时/失败后由调用方主动调用 retry
3. **at-least-once**：崩溃重执行可能使 handler 被执行多次（服务挂掉时副作用可能已发生），**业务方 handler 必须自行保证幂等**
4. **异步等待无超时**：WAIT_CONFIRM 无超时限制；用户永不回调时流程永久挂起，兜底出口 = cancel / resume / 强制终态
5. **回调幂等**：确认仅 `WAIT_CONFIRM → 终态` 的 CAS 生效一次，重复/晚到回调自动忽略
6. **多实例一致性**：所有状态流转均以 DB CAS 为权威；Redis 锁用于临界区互斥与执行中断判定；CAS 保证任何并发/恢复路径不产生双重终态

## 7. 数据模型草案（详细 DDL 见 05-数据库设计）

> 约束：所有 id 相关字段为 varchar；MySQL 5.6 无 JSON 类型，graph_json / result / biz_args 均以 TEXT 存储。

### 7.1 flow_definition（流程定义 · 静态，固定流程复用）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | varchar(64) PK | 定义 id |
| biz_type | varchar(64) | 业务类型 |
| biz_id | varchar(64) | 业务主键 |
| graph_json | text | DAG 图（nodes 节点数组 + edges 边数组） |
| version | int | 版本 |
| status | varchar(16) | ENABLE / DISABLE |
| created_at / updated_at | datetime | — |
| 唯一约束 | UNIQUE(biz_type, biz_id) | 一个业务类型 + 主键对应一份固定定义 |

### 7.2 task_instance（任务表）

| 字段 | 类型 | 说明 |
|---|---|---|
| task_id | varchar(64) PK | 任务 id（引擎生成） |
| biz_type | varchar(64) | 业务类型 |
| biz_id | varchar(64) | 业务主键 |
| graph_json | text | 本次运行图快照（固定流程取定义，自定义流程取提交） |
| state | varchar(16) | RUNNING / SUCCESS / FAILED / CANCELLED |
| biz_args | text | 业务参数 JSON |
| started_at / finished_at / created_at / updated_at | datetime | — |
| 唯一约束 | UNIQUE(biz_type, biz_id) | 幂等键：重复提交返回已有任务 |

### 7.3 node_instance（节点表，提交任务时由 graph_json 解析生成）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | varchar(64) PK | 节点实例 id（引擎生成） |
| task_id | varchar(64) | 所属任务 |
| biz_node_id | varchar(64) | 用户自定义流程中标识节点的唯一 id |
| handler | varchar(128) | 执行器名称，**与 @Component 注解名称一致** |
| state | varchar(16) | PENDING / RUNNING / WAIT_CONFIRM / SUCCESS / FAILED / CANCELLED |
| result | text | 执行结果（handler 回写，可空；超时/异常由引擎填写） |
| biz_args | text | 节点业务参数（来自 graph_json nodes[].biz_args，执行器经 NodeContext.nodeArgs 读取） |
| time_out | tinyint | 是否超时（引擎填写，默认 0） |
| async_type | tinyint | 0 同步 / 1 异步（来自 graph_json 节点定义） |
| started_at / finished_at / created_at / updated_at | datetime | — |
| 唯一约束 | UNIQUE(task_id, biz_node_id) | — |
| 索引 | INDEX(task_id) | 按任务查询节点 |

### 7.4 task_trace（任务流水表 · 运行轨迹）

> 单表双状态：同时呈现任务整体状态（task_state）与节点局部状态（node_state），按 taskId + 时间排序还原完整运行轨迹。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | varchar(64) PK | 流水 id |
| task_id | varchar(64) | 所属任务 |
| node_id | varchar(64) | 节点实例 id（节点级事件；任务级为空） |
| biz_node_id | varchar(64) | 节点业务 id（可读性） |
| event_type | varchar(32) | TASK_SUBMIT / NODE_CLAIM / NODE_SUCCESS / NODE_FAILED / NODE_WAIT_CONFIRM / NODE_CONFIRM / NODE_TIMEOUT / NODE_RESET / RESUME / NODE_CANCEL / TASK_CANCEL / RETRY / FORCE_FINALIZE |
| task_state | varchar(16) | 事件后任务状态（快照，整体维度） |
| node_state | varchar(16) | 事件后节点状态（节点级事件） |
| detail | text | 附加信息（来源 / 模式 / 结果 / 操作） |
| created_at | datetime | 事件时间 |
| 索引 | KEY(task_id, created_at)；KEY(node_id, created_at) | 全轨迹 / 单节点轨迹 |

记录规则：任务级事件只填 task_state；节点级事件同时填 task_state（冗余快照）+ node_state；节点终态触发任务收敛时，同一条流水的 task_state 直接记收敛终态（最后一行流水 = 任务最终状态）。重试 = RETRY（任务级）+ NODE_RESET ×N（节点级）；续跑 = RESUME（节点级）。

## 8. 验收标准（细化见 08-测试与验收）

1. dag-demo 一键启动，跑通：串行 / 并行 / 汇聚 / 异步回调 / 超时 / 取消 / 重试（两种模式）/ resume 全场景
2. 多实例模拟：同一节点不被重复执行（单元级验证 CAS + 锁）
3. 崩溃模拟：执行中 Kill 服务 → 重启 → 任务从 DB 恢复，异常节点重新调度
4. 自定义流程提交：合法 JSON 执行成功；非法（环 / handler 未注册 / 结构错误）被拒绝且不落库
