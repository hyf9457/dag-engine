## 4. 组合异常分析结论（异常叠加是否产生新异常）

**结论：所有组合均收敛到三个安全兜底，不存在"异常叠加产生新未覆盖状态"的路径。**

| 兜底层 | 机制 | 覆盖的异常类型 |
|---|---|---|
| ① 状态幂等 | 全部状态流转单条 CAS（领取 / 终态 / 收敛 / 回调 / 控制），行数判定，恰一个生效 | D 组全部竞态、F 组回调、H 组部分 |
| ② 执行兜底 | 锁判定（中断→重置重执行）+ 超时判定（挂起→FAILED）+ 兜底扫描（崩溃丢失推进） | A/B/C 组执行异常、EX-B05/B06 |
| ③ 语义兜底 | at-least-once + 业务 handler 幂等 + 人工三出口（cancel/resume/forceFinalize） | EX-A06/H01/H02/H03、永不回调 |

**关键推演验证**：

- **执行中 + MySQL 抖动**：不本地重试，写终态失败节点保持 RUNNING 持锁 → 超时兜底 FAILED；重试路径 = retry 重置 → 重新执行（业务幂等兜底副作用）。不会出现"节点状态与任务状态不一致"（短事务）。
- **执行中 + 实例挂 + Redis 挂**：降级已声明（超时 FAILED + 人工 retry），不产生半终态。
- **并发 cancel + 收敛**：任务 CAS 只允许一次 RUNNING→终态，终态二选一，流水一致（同事务）。
- **重试 + 新提交**：biz 幂等键挡住，不产生双任务。

## 5. 恢复机制总览（谁负责恢复）

| 异常类型 | 第一响应 | 兜底 | 最终态 |
|---|---|---|---|
| 执行中断（实例挂掉） | 统一巡检（锁可抢 → 重置） | — | 节点重执行 → 正常终态 |
| 业务挂起（超时） | 统一巡检（超时判定） | — | FAILED(time_out=1) |
| 进程崩溃丢失推进 | 兜底扫描 | — | 补推进 |
| 永不回调 | 人工三出口 | — | 终态（用户决策） |
| 并发竞态 | CAS 幂等 | — | 恰一个生效 |
| 基础设施抖动 | 本地重试（EX-01） | 超时兜底 / 人工 | 终态 |
| Redis 缺失降级 | 本地锁 + 关异常扫描 | 超时 FAILED / 人工 | 终态 |
