# 08 · 测试与验收（测试用例清单 v0.1）

> 基线：01-需求规格 / 02-架构设计 / 04-类图 / 05-数据库设计 / 06-接口设计。
> 本文件是**项目验收的唯一依据**：P0 用例必须全部通过，P1 通过率 ≥ 90% 方可交付。

---

## 1. 验收总则

### 1.1 测试环境

| 项 | 要求 |
|---|---|
| 运行时 | JDK 8 + Spring Boot 2.5.x，Maven 多模块（dag-core / dag-demo） |
| 数据库 | MySQL 5.6.x（utf8mb4），三张表：flow_definition / task_instance / node_instance + task_trace |
| Redis | Redis Cluster（Redisson RLock，watchdog 30s 自动续期）；另测无 Redis 降级场景 |
| 部署 | 至少 2 个应用实例共享同一 MySQL 库（验证多实例防重） |
| 测试框架 | JUnit 5 + Spring Boot Test + Testcontainers（或本地 MySQL/Redis） |

### 1.2 用例分级

| 级别 | 定义 | 验收要求 |
|---|---|---|
| **P0** | 核心功能 / 数据正确性 / 多实例防重 / 崩溃恢复，失败即不可交付 | 100% 通过 |
| **P1** | 重要边界、异常输入、运维操作 | 通过率 ≥ 90%，缺陷不得有绕过方案 |
| **P2** | 边界输入、健壮性、非核心体验（**性能测试暂不纳入验收**） | 通过率 ≥ 80%，缺陷需给出处理结论 |

### 1.3 验收流程

1. 执行全部用例，逐条勾选《§6 验收记录表》；
2. 任一 P0 失败 → 修复后重跑该用例及其关联用例；
3. 提交《验收报告》：用例数 / 通过数 / 失败清单及原因 / 遗留缺陷清单；
4. 遗留缺陷分两类：`可交付（有规避方案）` / `不可交付（影响核心路径）`。

## 2. 用例编号规则

`TC-{组}-{序号}`，组：A 提交校验 · B 拓扑执行 · C 状态收敛 · D 回调 · E 超时 · F 重试 · G 取消 · H 续跑 · I 轨迹运维 · J 并发防重 · K 异常恢复 · L 边界输入。
