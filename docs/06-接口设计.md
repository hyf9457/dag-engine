# 06・接口设计（设计稿 v0.1）

> 基线：`01-需求规格.md` / `02-架构设计.md` / `05-数据库设计.md`。
> 已确认：**无 HTTP 回调端点**，全部为进程内 API（dag-core 以 Spring Bean 注入业务方）。

---

## 1. 总览

| 类别 | 说明 |
|---|---|
| 流程定义输入 | graph_json（nodes + edges） |
| 引擎门面 | `DagEngine`（Spring Bean，业务方注入） |
| 执行器扩展 | `NodeHandler` 接口，业务方实现并以 `@Component` 注册（**handler 名 = Bean 名**） |
| 回调确认 | 仅进程内：`confirm / fail` |
| 异常 | `DagException(code, msg)`；幂等 / 状态不匹配场景不抛异常，返回 `false` 或已有结果 |

## 2. graph_json DSL 规范

### 2.1 结构

```json
{
  "nodes": [
    { "biz_node_id": "createOrder", "handler": "orderCreateHandler", "async_type": 0, "biz_args": { "channel": "app", "userLevel": "vip" } },
    { "biz_node_id": "pay",         "handler": "payHandler",         "async_type": 1 }
  ],
  "edges": [
    { "from": "createOrder", "to": "pay" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| nodes[].biz_node_id | 是 | 节点唯一 id（用户自定义，任务内唯一） |
| nodes[].handler | 是 | 执行器 Spring Bean 名，必须与 `@Component` 名称一致且已注册 |
| nodes[].async_type | 否 | 0 同步（默认）/ 1 异步（返回 pending 等待确认） |
| nodes[].biz_args | 否 | **节点业务参数**（JSON 对象），执行器经 NodeContext.nodeArgs 读取；缺省为空 |
| edges[].from / to | 是 | 依赖边，from 完成后 to 才可执行；引用必须存在于 nodes |

### 2.2 JSON Schema（结构校验）

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["nodes", "edges"],
  "properties": {
    "nodes": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "required": ["biz_node_id", "handler"],
        "properties": {
          "biz_node_id": { "type": "string", "minLength": 1, "maxLength": 64 },
          "handler":     { "type": "string", "minLength": 1, "maxLength": 128 },
          "async_type":  { "type": "integer", "enum": [0, 1] },
          "biz_args":    { "type": "object" }
        },
        "additionalProperties": true
      }
    },
    "edges": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["from", "to"],
        "properties": {
          "from": { "type": "string", "minLength": 1 },
          "to":   { "type": "string", "minLength": 1 }
        },
        "additionalProperties": false
      }
    }
  }
}
```

### 2.3 可执行性校验规则（GraphValidator，全部通过才允许落库）

| # | 规则 | 失败处理 |
|---|---|---|
| 1 | JSON 结构合法（Schema） | 拒绝，code=1001 |
| 2 | 至少 1 个节点 | 拒绝，code=1006 |
| 3 | nodes 中 biz_node_id 不重复 | 拒绝，code=1003 |
| 4 | edges 的 from/to 均存在于 nodes | 拒绝，code=1004 |
| 5 | 无环（拓扑排序 Kahn） | 拒绝，code=1002 |
| 6 | 每个 handler 可解析，且**大小写敏感精确匹配** Bean 名 | 拒绝，code=1005 |
| 7 | edges 不允许重复（同一 from→to 只允许一条边） | 拒绝，code=1001 |
| 8 | 孤立节点允许（无入边无出边 → 视为单节点任务，独立执行） | 不拒绝 |

> 自环（from==to）在规则 5 中一并判环拒绝。
> 多重边按规则 7 拒绝（已拍板）；孤立节点按规则 8 作为单节点任务独立执行（已拍板）。

## 3. 进程内 API 详设

### 3.1 DagEngine 门面

```java
public interface DagEngine {

  /** 提交固定流程（graph 取自 flow_definition，按 biz_type+biz_id 匹配） */
  TaskInfo submit(String bizType, String bizId, Map<String, Object> bizArgs);

  /** 提交自定义流程（直接携带 graph_json，校验可执行性后执行） */
  TaskInfo submit(String bizType, String bizId, String graphJson, Map<String, Object> bizArgs);

  /** 回调确认：仅 WAIT_CONFIRM 节点生效；重复/晚到返回 false（幂等） */
  boolean confirm(String nodeInstanceId, String resultJson);

  /** 回调失败：仅 WAIT_CONFIRM 节点生效；返回 false 表示未生效（状态不匹配） */
  boolean fail(String nodeInstanceId, String error);

  /** 取消：仅 RUNNING 任务可取消；终态返回 false */
  boolean cancel(String taskId);

  /** 重试：仅 FAILED 任务可重试；mode 见 RetryMode */
  TaskInfo retry(String taskId, RetryMode mode);

  /** 断点续跑：仅 WAIT_CONFIRM 节点可 resume；其他状态返回 false */
  boolean resume(String nodeInstanceId);

  /** 查询任务 */
  TaskInfo getTask(String taskId);

  /** 查询任务下全部节点 */
  List<NodeInfo> getNodes(String taskId);

  /** 查询任务运行轨迹（单表流水，按时间升序；nodeId 可空=全部） */
  List<TraceEntry> getTrace(String taskId, String nodeId);

  /** 运维强制终态（挂起兜底）：任务/节点 → 指定终态 */
  boolean forceFinalize(String taskId, FinalState state);
}

public enum RetryMode {
  CONTINUE,   // 仅重置非 SUCCESS 节点（FAILED/WAIT_CONFIRM → PENDING），成功节点保留
  RESTART     // 全部节点重置为 PENDING，全量重跑
}

public enum FinalState { SUCCESS, FAILED, CANCELLED }
```

### 3.2 NodeHandler 执行器接口（业务方实现）

```java
public interface NodeHandler {
  ExecutionResult execute(NodeContext context);
}

public class NodeContext {
  private String taskId;            // 任务 id
  private String nodeInstanceId;    // 节点实例 id（异步场景需透传给回调方）
  private String bizNodeId;         // 节点业务 id
  private String bizType;
  private String bizId;
  private Map<String, Object> bizArgs;          // 任务全局业务参数（submit 接口传入）
  private Map<String, Object> nodeArgs;         // 节点业务参数（graph_json nodes[].biz_args）
  private Map<String, Object> upstreamResults;  // 上游节点结果（key = biz_node_id，value = result 反序列化）
  // getter / setter
}

public class ExecutionResult {
  /** 同步完成 */
  public static ExecutionResult success(Object data);
  /** 同步显式失败 */
  public static ExecutionResult failure(String error);
  /** 异步挂起：节点进入 WAIT_CONFIRM，等待 confirm/fail */
  public static ExecutionResult pending();
  // 内部标记 kind: SUCCESS / FAILURE / PENDING；data 或 error
}
```

> 参数约定：NodeContext.bizArgs = 任务全局业务参数（submit 接口传入）；NodeContext.nodeArgs = 节点业务参数（graph_json nodes[].biz_args）。
> **运行期以 ExecutionResult.kind 为准**：同步节点（async_type=0）返回 pending() 同样进入 WAIT_CONFIRM（async_type 仅作声明标记，不一致时以返回值为准）。
> 同步节点：handler 返回 success (data) → 节点 SUCCESS，data 序列化写入 node_instance.result，供下游 `upstreamResults` 读取；返回 failure (err) 或抛异常 → 节点 FAILED。
> 异步节点：返回 pending () → 节点 WAIT_CONFIRM（无超时）；业务方异步完成后以 NodeContext 中的 nodeInstanceId 调 `confirm/fail`。

### 3.3 返回模型

```java
public class TaskInfo {
  private String taskId;
  private String bizType;
  private String bizId;
  private String state;          // RUNNING / SUCCESS / FAILED / CANCELLED
  private String graphJson;
  private Map<String, Object> bizArgs;
  private Date startedAt;
  private Date finishedAt;
}

public class NodeInfo {
  private String id;             // 节点实例 id（回调/续跑使用）
  private String taskId;
  private String bizNodeId;
  private String handler;
  private String state;          // PENDING / RUNNING / WAIT_CONFIRM / SUCCESS / FAILED / CANCELLED
  private String result;         // handler 回写；超时/异常由引擎填
  private boolean timeOut;
  private int asyncType;
  private Date startedAt;
  private Date finishedAt;
}

public class TraceEntry {
  private String id;
  private String taskId;
  private String nodeId;        // 节点级事件；任务级为空
  private String bizNodeId;
  private String eventType;     // TASK_SUBMIT / NODE_CLAIM / NODE_SUCCESS / ...
  private String taskState;     // 事件后任务状态（快照，整体维度）
  private String nodeState;     // 事件后节点状态（节点级事件）
  private String detail;        // 来源 / 模式 / 结果 / 操作信息
  private Date createdAt;
}
```

## 4. 错误码

| code | 含义 | 场景 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 图结构非法 / 多重边 | JSON Schema 校验失败 / edges 重复 |
| 1002 | DAG 存在环 | 拓扑排序检测 |
| 1003 | 节点 id 重复 | nodes 中 biz_node_id 重复 |
| 1004 | 边引用不存在 | edges 引用未定义节点 |
| 1005 | handler 未注册 | 容器中无对应 Bean |
| 1006 | 空图 | nodes 为空 |
| 2001 | 任务已存在（幂等） | 同 biz_type+biz_id 已提交 → 返回已有任务（非异常） |
| 2002 | 任务不存在 | getTask / 控制操作 |
| 3001 | 任务状态不允许 | cancel 非 RUNNING；retry 非 FAILED |
| 3002 | 节点状态不允许 | resume 非 WAIT_CONFIRM |
| 4001 | 回调已处理（幂等忽略） | 重复 / 晚到 confirm/fail，返回 false |
| 5001 | 系统异常 | 内部错误 |
| 9001 | 参数非法 | 空参 / null / 非法参数类型（submit / 控制操作入参） |

- 业务异常抛 `DagException(code, msg)`；幂等 / 状态不匹配的调用不抛异常，按表中语义返回 false 或已有数据

## 5. 典型调用时序（文字版，图见 03-时序图）

**提交固定流程**

1. `dagEngine.submit(bizType, bizId, bizArgs)` → 按 `UNIQUE(biz_type,biz_id)` 幂等检查
2. 不存在：读 flow_definition 的 graph_json → 校验 → 短事务落 task + nodes → push 根节点执行
3. 存在：直接返回已有 TaskInfo

**提交自定义流程**

1. `dagEngine.submit(bizType, bizId, graphJson, bizArgs)` → graph_json 校验（Schema / 环 / 引用 / handler）
2. 通过 → 落库执行；失败 → `DagException(100x)`

**异步回调**

1. 异步节点 handler 返回 pending () → 节点 WAIT_CONFIRM
2. 业务异步完成 → `dagEngine.confirm(nodeInstanceId, resultJson)` → 节点 SUCCESS → push 下游
3. 重复调用 → false（幂等）

**重试 / 取消 / 续跑**

- `retry(taskId, CONTINUE|RESTART)`：仅 FAILED；重置节点 → push 重新触发
- `cancel(taskId)`：仅 RUNNING；未开始节点 / 同步 RUNNING/WAIT_CONFIRM 按状态收敛
- `resume(nodeInstanceId)`：仅 WAIT_CONFIRM → 回 PENDING 重新执行
