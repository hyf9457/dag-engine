# 03 时序图（核心流程）

> 版本：v1.0（与 dag-core 已实现代码调用链逐字对应）
> 说明：本版时序图按「已落地的实现」绘制——push 推进 + 周期兜底扫描双路径、统一巡检器 NodeInspector、
> 短事务状态流转（节点终态 + 收敛 + 流水同事务）、三人工出口（cancel / resume / forceFinalize）。

## 1. 对象图例

| 对象 | 说明 |
| --- | --- |
| Biz | 接入方（业务系统），调用 DagEngine 进程内 API |
| DagEngineImpl | 门面：参数校验、幂等、解析校验、编排控制操作 |
| OperationService | 提交落库 / 取消 / 重试 / 强制终态（任务 CAS + 节点批量 + 流水，短事务） |
| Scheduler | 调度器：提交后立即推进 + 周期兜底扫描（先补收敛，再领就绪节点） |
| ClaimService | 领取调度：提交执行任务到线程池（push 与兜底汇合同一领取） |
| NodeExecutor | 节点执行器：加锁 → CAS 领取 → 调 handler → 按结果分发 |
| TransitionService | 节点状态流转事务：终态写 + 收敛 + 流水原子提交 |
| NodeInspector | 统一巡检器：锁判定（重置 / 超时 FAILED），本地锁降级时关闭 |
| TraceRecorder | 流水写入（task_state + node_state 单表双状态） |

## 1. 提交自定义流程 → push 推进串行

```mermaid
sequenceDiagram
    autonumber
    participant Biz
    participant Engine as DagEngineImpl
    participant Op as OperationService
    participant Sched as Scheduler
    participant Claim as ClaimService
    participant Exec as NodeExecutor
    participant Trans as TransitionService
    participant Handler as NodeHandler(echoHandler)
    participant Trace as TraceRecorder
    participant DB as MySQL

    Biz->>Engine: submit(bizType, bizId, graphJson, bizArgs)
    Engine->>DB: selectByBiz（幂等：已存在返回已有任务）
    Engine->>Engine: parse(graphJson) 结构校验 1001/1006
    Engine->>Engine: validate(graph) 可执行性 1002-1005（多重边拒绝/孤立节点允许）
    Engine->>Op: submitNew(task, nodes, source)
    Op->>DB: insert task( RUNNING ) + insertBatch nodes( PENDING ) + TASK_SUBMIT 流水
    Op-->>Engine: OK
    Engine->>Sched: scheduleTask(task)
    Sched->>Sched: convergeIfNeeded（收敛兜底：null 未收敛）
    Sched->>DB: selectByTaskId（节点 + 状态）
    Sched->>Sched: 根节点 A：前驱空 → 就绪
    Sched->>Claim: submitNode(A)
    Claim->>Exec: executor.execute(A)
    Exec->>DB: tryLock(dag:node:{A})
    Exec->>DB: claim(A) CAS PENDING→RUNNING + NODE_CLAIM 流水
    Exec->>Exec: 组装 NodeContext（全局 args + 节点 args + 上游 result）
    Exec->>Handler: execute(ctx)
    Handler-->>Exec: ExecutionResult(SUCCESS, result)
    Exec->>Trans: persistSyncSuccess(A)
    Trans->>DB: finishSuccess(A) CAS RUNNING→SUCCESS
    Trans->>Trans: convergeIfNeeded（A SUCCESS、B PENDING → 不收敛）
    Trans->>DB: NODE_SUCCESS 流水（task_state=RUNNING）
    Trans-->>Exec: true
    Exec->>Claim: pushDownstream(A → B)
    Claim->>Sched: 找到后继 B，前驱 A=SUCCESS → submitNode(B)
    Claim->>Exec: execute(B)
    Exec->>DB: claim(B) CAS + NODE_CLAIM
    Exec->>Handler: execute(B)
    Handler-->>Exec: ExecutionResult(SUCCESS)
    Exec->>Trans: persistSyncSuccess(B)
    Trans->>DB: finishSuccess(B) CAS
    Trans->>DB: convergeSuccess 单条原子 SQL（全 SUCCESS）→ task RUNNING→SUCCESS + finished_at
    Trans->>DB: NODE_SUCCESS 流水（task_state=SUCCESS 收敛合并）
    Exec-->>Biz: 查询 getTask → SUCCESS
```

关键点：
- **幂等**：submit 前 selectByBiz；并发提交由 UNIQUE(biz_type,biz_id) 兜底（DuplicateKeyException → 返回先提交者）。
- **领取顺序**：先 tryLock 再 CAS claim；行数=1 生效，=0 竞态作废（多副本/双路径天然去重）。
- **收敛**：任一节点终态触发；单条原子 SQL（NOT EXISTS 全 SUCCESS / EXISTS 任一 FAILED），并发下由「兜底扫描先补收敛」保证不漏（EX-B07 自愈）。

## 2. 并行分支 + 汇聚

```mermaid
sequenceDiagram
    autonumber
    participant Sched as Scheduler
    participant Claim as ClaimService
    participant Exec as NodeExecutor
    participant Trans as TransitionService
    participant DB as MySQL

    Note over Sched,DB: 提交 A→B、A→C（B、C 并行）
    Sched->>Claim: submitNode(A)
    Claim->>Exec: execute(A)
    Exec->>DB: claim(A) + execute + finishSuccess(A)
    Exec->>Claim: pushDownstream(A → B, C)
    Claim->>Exec: execute(B)（线程池并发）
    Claim->>Exec: execute(C)（线程池并发）
    par B 与 C 并发领取
        Exec->>DB: tryLock(B) + claim(B) CAS
        Exec->>DB: tryLock(C) + claim(C) CAS
    end
    Exec->>Trans: persistSyncSuccess(B) / persistSyncSuccess(C)
    Trans->>DB: 各自 finishSuccess CAS（行锁串行，锁序 node→task→trace 不交叉）
    Note over Trans,DB: 若双方事务快照互相看不到对方提交（并发漏收敛），由兜底扫描 convergeIfNeeded 补齐
    Trans->>DB: convergeSuccess（B、C 均 SUCCESS）→ task SUCCESS

    Note over Sched,DB: 汇聚：A→C、B→C
    Sched->>Claim: submitNode(A)、submitNode(B)
    Exec->>DB: finishSuccess(A)、finishSuccess(B)
    Exec->>Claim: pushDownstream(A→C)、pushDownstream(B→C)
    Note over Claim,DB: C 的前驱需 A、B 均 SUCCESS 才就绪；首次只提交一次（CAS 保证只执行一次）
    Claim->>Exec: execute(C)
    Exec->>DB: claim(C) CAS + finishSuccess(C) + 收敛 SUCCESS
```

## 3. 异步节点回调确认（WAIT_CONFIRM）

```mermaid
sequenceDiagram
    autonumber
    participant Biz
    participant Engine as DagEngineImpl
    participant Exec as NodeExecutor
    participant Handler as NodeHandler(asyncHandler)
    participant Trans as TransitionService
    participant Claim as ClaimService
    participant DB as MySQL

    Exec->>Handler: execute(ctx)
    Handler-->>Exec: ExecutionResult(PENDING)  ← 异步等待（async_type=1，无超时）
    Exec->>Trans: persistWaitConfirm(B)
    Trans->>DB: markWaitConfirm(B) CAS RUNNING→WAIT_CONFIRM + NODE_WAIT_CONFIRM 流水
    Exec-->>Biz: 任务保持 RUNNING，B 等待业务方回调
    Note over Biz,DB: 业务方异步处理完成后，通过进程内 API 主动回调（无 HTTP 端点）
    Biz->>Engine: confirm(B.nodeId, resultJson)
    Engine->>DB: selectById + 校验 WAIT_CONFIRM
    Engine->>Trans: persistConfirmSuccess(B)
    Trans->>DB: confirmSuccess(B) CAS WAIT_CONFIRM→SUCCESS（行数=0 → 重复回调幂等忽略 4001）
    Trans->>DB: convergeIfNeeded + NODE_CONFIRM 流水
    Trans-->>Engine: true
    Engine->>Claim: pushDownstream(B → C)
    Claim->>Exec: execute(C) ...（推进后续）
    Note over Biz,DB: 失败回调：fail(B.nodeId, error) → confirmFailed CAS → FAILED + 收敛 FAILED
```

## 4. 人工控制：取消 / 重试 / 续跑

```mermaid
sequenceDiagram
    autonumber
    participant Biz
    participant Engine as DagEngineImpl
    participant Op as OperationService
    participant Sched as Scheduler
    participant DB as MySQL

    Note over Biz,DB: 取消（仅 RUNNING）
    Biz->>Engine: cancel(taskId)
    Engine->>DB: selectByTaskId + 校验 RUNNING（终态拒绝）
    Engine->>Op: cancelTask(task)
    Op->>DB: task CAS RUNNING→CANCELLED + 非终态节点批量 CANCELLED + TASK_CANCEL/NODE_CANCEL 流水
    Op-->>Biz: true

    Note over Biz,DB: 重试（仅 FAILED，用户选择模式）
    Biz->>Engine: retry(taskId, mode=CONTINUE|RESTART)
    Engine->>DB: 校验 FAILED（其他状态抛 3001）
    Engine->>Op: retryTask(task, mode)
    Op->>DB: task CAS FAILED→RUNNING（finished_at 置空）
    Op->>DB: CONTINUE → 仅重置 FAILED/WAIT_CONFIRM；RESTART → 重置全部
    Op->>DB: RETRY + NODE_RESET(source=retry/retry-restart) 流水
    Engine->>Sched: scheduleTask(task)（重置后重新推进，task_id 不变）

    Note over Biz,DB: 续跑（仅 WAIT_CONFIRM 节点）
    Biz->>Engine: resume(nodeId)
    Engine->>DB: 校验 WAIT_CONFIRM（其他状态拒绝）
    Engine->>Trans: persistResume → CAS WAIT_CONFIRM→PENDING + RESUME 流水
    Engine->>Sched: scheduleTask(task)（重新领取执行）
```

## 5. 统一巡检器 NodeInspector（崩溃恢复 + 超时判定）

```mermaid
sequenceDiagram
    autonumber
    participant Runner as ScanRunner(@Scheduled)
    participant Sched as Scheduler
    participant Inspect as NodeInspector
    participant Lock as LockManager(Redis)
    participant Trans as TransitionService
    participant DB as MySQL

    Runner->>Sched: scanAndSchedule()（兜底扫描：先补收敛，再领就绪节点）
    Runner->>Inspect: inspect()
    Inspect->>DB: selectRunningNodes（state=RUNNING，含 started_at，LIMIT 防全表）
    loop 每个 RUNNING 节点
        Inspect->>Lock: tryLock(dag:node:{id}, 0ms)
        alt 抢到锁（执行器已死 / 已释放，无人持有）
            Lock-->>Inspect: true
            Inspect->>Trans: persistResetInspect(node)
            Trans->>DB: resetRunning CAS RUNNING→PENDING + NODE_RESET(source=inspect) 流水
            Note over DB: 下轮调度重新领取执行（崩溃恢复，不误判为超时失败）
        else 抢不到锁（执行器存活 / 正在执行）
            Lock-->>Inspect: false
            Inspect->>Inspect: 超时判定 started_at < now - timeoutSeconds
            alt 超阈值（且节点非异步等待）
                Inspect->>Trans: persistTimeout(node, deadline)
                Trans->>DB: timeoutFail CAS（state=RUNNING AND started_at<deadline）→ FAILED + time_out=1 + result='timeout' + NODE_TIMEOUT 流水
                Trans->>DB: convergeIfNeeded → 任务收敛 FAILED
            else 未超时 / 异步等待节点
                Note over Inspect: 跳过（异步 WAIT_CONFIRM 无超时限制）
            end
        end
    end
```

关键点：
- **锁判定优先于超时判定**：tryLock(0) 成功 = 执行器已死 → **重置 PENDING**（绝不误判为超时失败）；失败 = 存活 → 才看超时。
- Redis 锁 watchdog 自动续期（30s 租期 / 10s 续期），慢执行不会丢锁被误重置。
- **Redis 缺失降级 LocalLockManager 时，inspect 直接 return**（本地锁无法感知其他实例，异常巡检自动关闭，防跨实例误重置）。

## 6. 兜底扫描补收敛（EX-B07 自愈路径）

```mermaid
sequenceDiagram
    autonumber
    participant Runner as ScanRunner
    participant Sched as Scheduler
    participant StateM as TaskStateMachine
    participant DB as MySQL

    Runner->>Sched: scanAndSchedule()
    Sched->>DB: selectRunningTasks(batchSize)
    loop 每个 RUNNING 任务
        Sched->>StateM: convergeIfNeeded(taskId)
        StateM->>DB: convergeFailed（单条原子 SQL：EXISTS FAILED）
        StateM->>DB: convergeSuccess（单条原子 SQL：NOT EXISTS 非 SUCCESS）
        alt 收敛成功（终态）
            StateM-->>Sched: SUCCESS/FAILED
            Note over Sched: 任务已终态，跳过节点推进（下轮不再扫描）
        else 未收敛
            Sched->>DB: 遍历 PENDING 节点，前驱全 SUCCESS → submitNode 推进
        end
    end
```

> 该路径解决：并行节点终态事务基于各自一致性快照判定，可能双方都「看不到」对方提交而漏收敛；
> 兜底扫描在每个推进入口先补一次幂等收敛（单条 CAS），收敛漏触发最终自愈，最多延迟一个扫描周期。

## 7. 状态机总览（任务 / 节点）

| 对象 | 状态 | 迁移 | 触发 |
| --- | --- | --- | --- |
| task | RUNNING | → SUCCESS | 全节点 SUCCESS（CAS 单条 SQL） |
| task | RUNNING | → FAILED | 任一节点 FAILED（CAS） |
| task | RUNNING | → CANCELLED | cancel / forceFinalize(CANCELLED) |
| task | FAILED | → RUNNING | retry（唯一例外路径，finished_at 置空） |
| node | PENDING | → RUNNING | 领取：tryLock + CAS claim |
| node | RUNNING | → SUCCESS | handler SUCCESS / confirm |
| node | RUNNING | → FAILED | handler FAILED / fail 回调 / 超时（time_out=1） |
| node | RUNNING | → WAIT_CONFIRM | handler PENDING（无超时） |
| node | RUNNING | → PENDING | 巡检重置（执行器已死） |
| node | WAIT_CONFIRM | → PENDING | resume / retry(CONTINUE 含 WAIT_CONFIRM) |
| node | FAILED / WAIT_CONFIRM | → PENDING | retry 重置 |
| node | 任意非终态 | → CANCELLED | cancel / forceFinalize |
